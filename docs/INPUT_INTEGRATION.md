# Native input integration audit

The headset and controller hardware work. A compiled native left-stick adapter is now available only through an explicit bounded movement trial; it now passes the first live standalone movement/release trial; physical headset movement remains pending.

The installed Engine.dll exports UViewport::ReadInput(float), which calls UInput::ReadInput(float,FOutputDevice&). Its audited code obtains the input object from viewport+0x78; that object's +0xea4 points back to the viewport. The viewport's +0x34 controller and the script input object's Outer were verified against the one local KFPlayerController. These are this installed build's observed relationships, not portable UE2 offsets.

Live reflected controller axes are ten consecutive FloatProperty values at offsets 1348 through 1384: aBaseX, aBaseY, aBaseZ, aMouseX, aMouseY, aForward, aTurn, aStrafe, aUp, aLookUp. PlayerInput is an ObjectProperty at 2160. Fire/alternate fire belong to the inherited Controller class (ByteProperty at 889/890), not PlayerController. Descriptor metadata is evidence; an external snapshot does not authorize unsynchronized writes.

Read-only native trial native-trace-20260925-190036-910911 observed 240 input calls on thread 53768: 120 positive-delta passes and 120 sentinel passes with DeltaTime=-1. 117 complete PlayerTick observations followed positive-delta reads; no sentinel pass was consumed as a PlayerTick sample. All axis values were finite, all game input values were left unchanged, and the extra ReadInput hook plus all original trace hooks restored. Early samples precede completion of the other instrumentation hooks and are not counted as full tick observations.

The native ReadInput function scales FloatProperty input values by 20/DeltaTime for a normal pass and zero for the sentinel. Default forward/strafe aliases specify Speed 300. Thus controllers must be inserted at a verified positive-delta boundary, not both passes. The later nonzero trial confirms the expected scaling through PlayerTick and corresponding pawn displacement; physical headset control still needs acceptance.

KFPlayerController.PlayerTick calls the inherited PlayerTick. Engine.PlayerController then calls PlayerInput.PlayerInput, Pawn.RawInput and PlayerMove. KFPlayerInput remaps aBaseY into aForward, aBaseX/mouse into aTurn, applies weapon/FOV sensitivity, and clears raw base axes. KF UpdateRotation uses 32*DeltaTime*aTurn and applies recoil. Movement uses pawn forward/right axes and the existing native movement/replication path.

The adapter validates local pawn ownership/liveness, consumes focused unexpired controller samples and requires radial neutral after interruption, recenter or respawn. At the measured positive-delta boundary, it temporarily writes 6000 times normalized stick demand into aBaseY/aStrafe and restores those raw properties after PlayerTick. The live nonzero trial now verifies this scaling through PlayerTick. Unavailable controls leave normal flat input alone. No writes are enabled in the default trace or headset commands. HMD view remains independent of weapon aim. Controller weapon transforms, server-authoritative firing and full physical manipulation require separate adapters.

No custom script input class was installed: KFPlayerController.InitInputSystem explicitly resets InputClass to KFPlayerInput, so a naive class-setting approach would not persist. The SDK source and binary audit stay in ignored local/report storage.

Offline validation: x86 18/18 and x64 17/17 suites pass. ControllerLocomotion tests cover radial mapping, diagonal bounds, duplicate samples, held startup, focus loss, controller tracking loss, pawn change, recenter, pause/death, mailbox absence, long gaps, backwards sequence/time and invalid analog values. The real x64/x86 mailbox probe still passes expiry/focus/peer-loss releases without a game or headset. A separate synthetic fixture check proves the result validator rejects zero-only input, stuck movement after focus loss, missing phases and restoration failure; this is not engine evidence.

When the owner is ready to reopen a standalone match, first run `tools/native_bridge_trial.py --pid <new PID> --game <game path> --movement`. It verifies process/world/binary identity anew and sends a 7.5-second sequence: neutral, small forward demand, neutral, small strafe demand, focus loss, held-focus recovery, neutral, backwards demand, delivery silence, held recovery, neutral. The native report records demand, axes consumed by PlayerTick and restoration. The checker requires nonzero consumption and neutral interruption phases. Actual pawn displacement and collisions still need observation. Then `tools/native_headset_trial.py ... --movement` enables the physical left stick for the bounded headset test. Turning, controller weapon aim and interaction remain separate next stages. The owner asked to close KF temporarily, so neither live movement command was run at this checkpoint.

Live evidence: native-trace-20260925-193320-142487 and native-bridge-20260925-193320 pass every movement/release phase, with 382/382 raw-input restorations and all hook/resource cleanup verified. Forward/strafe/backward demand reached the native gameplay path; independent read-only position sampling observed corresponding pawn travel. The initial run failed because exhaustive receiver pixel counting delayed controls beyond the existing 100 ms expiry. Movement-mode image verification now checks the first pair exhaustively and every pair's identity/GPU copies, allowing uninterrupted controller delivery. Input expiry/neutral rearming remain unchanged. Physical headset movement is the next acceptance item.
